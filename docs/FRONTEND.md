# Frontend guide (Vibe Budgeting X)

Read `docs/ARCHITECTURE.md` first. This document is the contract for everyone building screens in
`frontend/`. When this file and your habits disagree, follow this file.

## Commands (run in `frontend/`)

| Command | What it does |
| --- | --- |
| `npm run dev` | Vite on http://127.0.0.1:5173, `/api` and `/static` (bank logos) proxied to `http://127.0.0.1:5001` (override with `VBX_API_TARGET`) |
| `npm run dev:mock` | Same, but `/api/auth/*` and `/api/bootstrap` are answered by `src/dev/mock-api.ts` (any username logs in; password `wrong` fails). Other `/api` calls still go to the proxy. |
| `npm run build` | `tsc -b` + production build into `dist/` |
| `npm run lint` | ESLint, zero warnings allowed |
| `npm run format` | Prettier (with Tailwind class sorting) |
| `npm test` | Vitest + Testing Library (jsdom), then `scripts/pwa-check.mjs` (PWA checks on the built SPA served by the real backend); `npm run test:unit` = Vitest only |
| `npm run e2e` | Playwright, every spec in `e2e/` against the real backend. Base URL from `VBX_E2E_BASE` (e.g. the production build on :5002); without it Playwright starts Vite on :5174 (proxying to :5001). Output per run in `test-results/<run>/`; traces only with `VBX_E2E_TRACE=1` |
| `node e2e/seed/seed.mjs <base> [user]` | Rich demo data through the API (18 months, a credit card, rules, budgets, a shared group, investments); throwaway databases only |
| `npm run gen:api` | Regenerates `src/api/schema.d.ts` from the running backend's `/openapi.json` |

`/dev/components` (dev server only) shows every building block with sample data.

### Feature folders and file naming

Each screen lives in `src/features/<feature>/` where `<feature>` is the backend domain name
(`expenses`, `income`, `recurring`, `transfers`, `budget`, `shared`, `reports`, `investments`,
`yearly`, `summary`, `settings`, `home`, `more`).

| File | Content |
| --- | --- |
| `<Name>Page.tsx` | the routed screen, `export default function <Name>Page()` |
| `api.ts` | the feature's query keys, query hooks and mutation hooks (no JSX) |
| `<Thing>Sheet.tsx` / `<Thing>Form.tsx` | sheets and forms of this feature |
| `<thing>.ts` + `<thing>.test.ts` | pure logic of this feature and its test |
| `*.test.tsx` | component tests next to the component |

Components: `PascalCase.tsx`, one main export. Hooks/helpers: `camelCase.ts`. A `.tsx` file exports
only components (React Fast Refresh rule, enforced by lint); put hooks/constants in a `.ts` file.

Do not import from another feature's folder. If two features need the same thing, move it to
`src/components/` or `src/lib/` (tell the orchestrator; those folders are shared).

## Adding a screen

1. Create `src/features/things/ThingsPage.tsx`:

   ```tsx
   import { PageHeader } from '@/components/PageHeader'
   import { MonthSwitcher } from '@/components/MonthSwitcher'
   import { useT } from '@/i18n'

   export default function ThingsPage() {
     const t = useT()
     return (
       <>
         <PageHeader title={t('nav.things')} />
         <MonthSwitcher className="-ml-2 mb-2" />
         {/* content */}
       </>
     )
   }
   ```

2. Register the route in `src/app/router.tsx` (inside the authenticated children):
   `{ path: 'things', lazy: page(() => import('@/features/things/ThingsPage')) }`
3. Add it to `NAV_ITEMS` in `src/app/nav.ts` (the sidebar and the More page pick it up).
4. Add the strings to `src/i18n/el.ts` and `src/i18n/en.ts`.

All existing sections already have a route and a placeholder page (`ScreenPlaceholder`). To build a
screen, replace the body of its existing `*Page.tsx`; do not rename the file or the route.

Screens never add outer padding or safe-area insets: the `AppShell` does that. They render a
`PageHeader` (it sets the `<h1>` and the document title) and then content.

## Data fetching

All server types come from the generated schema: `Schema<'ExpenseOut'>` (see `src/api/types.ts`).
Check the exact request/response model of an endpoint in `paths["/api/..."]` of `schema.d.ts`.
Run `npm run gen:api` with the backend running whenever the API changes; commit the result. No
hand-written response types.

Put the feature's data layer in `features/<feature>/api.ts`:

```ts
import { useMutation, useQuery, useQueryClient } from '@tanstack/react-query'
import { toast } from 'sonner'
import { api } from '@/api/client'
import { createKeys, invalidateMoney } from '@/api/keys'
import type { Schema } from '@/api/types'
import { translate } from '@/i18n'

type Expense = Schema<'ExpenseOut'>
// Clashing model names are namespaced by the generator; look them up in schema.d.ts.
type ExpenseIn = Schema<'vbx__api__schemas__expenses__ExpenseIn'>
export const expenseKeys = createKeys('expenses')

export function useExpenses(month: string) {
  return useQuery({
    queryKey: expenseKeys.list({ month }),
    queryFn: () => api.get<Schema<'ExpenseListOut'>>('/expenses', { params: { month } }),
  })
}

export function useCreateExpense() {
  const qc = useQueryClient()
  return useMutation({
    mutationFn: (body: ExpenseIn) => api.post<Expense>('/expenses', body),
    onSuccess: () => {
      void invalidateMoney(qc)          // balances, home, reports... all change
      toast.success(translate('common.saved'))
    },
  })
}
```

### Query key conventions

- Always build keys with `createKeys('<domain>')`; the first element is the domain name.
  `keys.all` = `['expenses']`, `keys.list(filters)` = `['expenses','list',{...}]`,
  `keys.detail(id)`, `keys.custom('name', ...parts)`.
- Filters (month, account, search) go into the key object, never into closures only.
- After a mutation:
  - it moves money (expense, income, transfer, recurring post, shared settlement, account balance):
    `invalidateMoney(qc)` (invalidates bootstrap, home and every money domain);
  - otherwise: `qc.invalidateQueries({ queryKey: keys.all })` plus any other domain it affects
    (renaming a category also changes `qk.bootstrap`).
- Do not use `setQueryData` for server data except for optimistic updates you also roll back, or to store a
  response that IS the fresh server state (investments: price refresh, cache-only reload after a save).

### Invalidation matrix (mutation -> invalidated query keys)

`MONEY` = `invalidateMoney(qc)` = `bootstrap`, `home`, `accounts`, `categories`, `expenses`, `income`,
`recurring`, `transfers`, `budget`, `shared`, `reports`, `yearly`, `summary`. Every screen that shows a balance,
a total or an entry count reads one of these, so a money mutation anywhere refreshes the account balances
(Home, Transfers, Settings -> accounts, Summary), Home, Summary, Yearly, Budget, the reports and the category
counts at once.

| Mutation (hook) | Invalidates |
| --- | --- |
| expense / income create, edit, delete (`useSaveEntry`, `useDeleteEntry`, quick add) | MONEY |
| transfer create / delete (`useCreateTransfer`, `useDeleteTransfer`) | MONEY |
| recurring rule create / edit / delete (`useSaveRecurring`, `useDeleteRecurring`) | MONEY (the bootstrap refetch posts due entries) |
| bootstrap response with `posted_recurring > 0` (`useBootstrapSync`) | MONEY except `bootstrap` |
| account create / edit / delete (`useSaveAccount`, `useDeleteAccount`) | MONEY + `settings` (Telegram default account) |
| category create / rename / delete (`useSaveCategory`, `useDeleteCategory`) | `categories`, `bootstrap`, `expenses`, `income`, `recurring`, `budget`, `reports`, `summary`, `yearly`, `home` |
| budget toggle (`useToggleBudget`) | `budget`, `home`, `summary`, `reports`, `bootstrap` |
| budget defaults / override / clear / restore month | `budget`, `home`, `summary`, `reports` |
| shared: bill create / edit / delete, record / unrecord my share, payment create / delete / record / unrecord, delete group, leave group | MONEY |
| shared: people add / rename / link / unlink / remove, group create / rename, members add / remove, accept / decline invitation | `shared` |
| investments: transaction create / edit / delete | `reports`, `home`; the screen is set at once from `GET /api/investments?live=false` (database + cached prices), then `investments` is invalidated (live lookup in the background) |
| investments: refresh prices (`useRefreshPrices`) | sets `['investments','screen']` to the response |
| settings: AI / Telegram saves, link code, unlink, default account, notifications | `['settings','integrations']` |
| Excel import (`useImportExcel`) | everything (`qc.invalidateQueries()`) |
| login / register / logout | every query except the session is removed |

### Defaults you get (src/app/query-client.ts)

- `staleTime` 30 s, no refetch on window focus, no retry on 4xx, one retry on network/5xx.
- Errors are toasted globally (the server's `detail`). If the component shows the error itself
  (inline form validation), pass `meta: { toastErrors: false }` and render
  `<FieldError>{errorMessage(mutation.error)}</FieldError>`.
- 401 anywhere: the session is marked logged out and the guard sends the user to
  `/login?next=<page>`. Never handle 401 in a screen.
- CSRF: the client adds `X-CSRF-Token` to every non-GET request. Nothing to do.
- Loading: show `ListSkeleton`/`CardSkeleton` while `isPending`; empty lists get `EmptyState`.

### Reference data

`useBootstrap()` gives the `/api/bootstrap` payload (user, accounts with balances, categories,
income categories, tag names, budget on/off, server `today` and `month`). It is loaded once before the
shell renders, so it is always defined inside screens. `useToday()` returns the server's day; use
it (not `new Date()`) for form defaults. After changing accounts/categories invalidate `qk.bootstrap`.

### Month

Screens that show a month use `const { month } = useMonth()` (URL `?month=YYYY-MM`, default current
month, kept when navigating through the tab bar/sidebar) and render `<MonthSwitcher />`. Pass
`month` to the query key and to the API params.

## Money, amounts, dates

- Display: `<Money value={x} />` or `formatMoney(x, { signed, currency })`. Never `toFixed` or
  `toLocaleString` for money. `formatMoney` mirrors the old `money` filter (`1.527,08 €`,
  `-12,00 €`, `+5,00 €` with `signed`, `$1.234,50` for stock quotes, `—` for missing).
- Colour: `<Money tone="all|positive|none">`; the sign is always in the text, colour is extra.
  Expense lists use `tone="positive"` (the default in `ListRow`).
- Input: amount state is a string (`''`, `'12.5'`); `<AmountEntry>` + `<AmountKeypad>` on mobile,
  `<AmountInput>` on desktop. Convert with `parseAmountInput(text)` (accepts `12,50` and `12.50`;
  returns `null` for blank/invalid). Sign conventions are the backend's: send what the old form sent.
- Dates are `YYYY-MM-DD` strings. Use `relativeDayLabel(iso, lang, today)` for list headings
  (Σήμερα / Χθες / weekday / date), `monthLabel(month, lang)`, `<DatePicker>` for picking a day.
  Never `new Date('YYYY-MM-DD')` (UTC); use `parseISODate`.

## Strings (i18n)

Every user-visible string goes through `t()`:

```tsx
const t = useT()
<p>{t('budget.remaining', { amount: formatMoney(rest) })}</p>
```

- Add the key to `src/i18n/el.ts` (the key source, natural Greek) and the same key to `en.ts`
  (TypeScript fails the build if one is missing). Use `{name}` placeholders.
- Key naming: `<feature>.<name>` (`expenses.addTitle`, `budget.overBy`); shared words in `common.*`.
  Group each feature's keys together with a comment line, to keep merges between parallel branches
  simple.
- Outside React (e.g. in a mutation callback) use `translate(key, params)`.
- Server messages (`detail`) are shown as they come; do not translate them client-side.

## Sheets, dialogs, toasts

- Forms and details open in `ResponsiveSheet` (bottom drawer with drag-to-close on mobile, centred
  dialog on desktop, focus trapped, Escape closes):

  ```tsx
  <ResponsiveSheet open={open} onOpenChange={setOpen} title={t('expenses.addTitle')}
    footer={<Button size="block" onClick={save} disabled={create.isPending}>{t('common.save')}</Button>}>
    <AmountEntry value={amount} onChange={setAmount} />
    <FieldLabel id={catLabel}>{t('common.category')}</FieldLabel>
    <ChipPicker labelledBy={catLabel} label={t('common.category')} bleed={!isDesktop}
      value={categoryId} onChange={setCategoryId}
      options={boot.categories.map((c) => ({ value: c.id, label: c.name, icon: <CategoryGlyph name={c.name} /> }))} />
    {!isDesktop && <AmountKeypad value={amount} onChange={setAmount} className="mt-4" />}
  </ResponsiveSheet>
  ```

- The back button (browser, Android gesture) closes an open sheet instead of leaving the screen
  (`useBackToClose`, built into `ResponsiveSheet`; the router never sees these same-page history steps).
- Save handlers call `useMutationLock(mutation).take()` right before `mutate` (two quick taps or tap + Enter
  must not save twice; `isPending` alone updates a tick too late) and disable the button while pending.
- Destructive actions: `const confirm = useConfirm(); if (await confirm({ title, destructive: true })) ...`
  or `<ConfirmDialog>`. `window.confirm` is banned by lint.
- Feedback: `toast.success(t('common.saved'))` after a successful mutation; errors are automatic.
- The "+" button opens the quick-add sheet (`features/expenses/QuickAddExpense.tsx`, with the
  Expense / Income switch). Open it from anywhere with `useQuickAdd().open({ kind })`.

`ChipPicker`, `DatePicker`, `CategoryIcon`/`CategoryGlyph`/`IconTile`, `TagText` (`#tags` as links to

Look at `/dev/components` before writing a new component; reuse first.

## Styling rules

- Tailwind utility classes with the theme tokens only: `bg-card`, `text-muted-foreground`,
  `bg-primary`, `text-positive`/`text-negative`/`text-warning`, `bg-hero`. No hex colours in
  components (they would break the 5 themes × light/dark).
- Cards: `rounded-2xl border bg-card shadow-card` (`<Panel>`); lists: `<ListGroup>`.
- Touch targets at least 44px on mobile: `Button size="touch" | "block" | "icon-touch"`.
- Mobile first: write the 390px layout, add `md:` for desktop (sidebar layout starts at 768px).
  `useIsDesktop()` only when behaviour differs (keypad vs input), not for styling.
- Icon-only buttons need `aria-label`; decorative icons `aria-hidden`.
- Motion: CSS transitions only; `prefers-reduced-motion` is handled globally.

## Keeping bundles small

- Every screen is a lazy route; do not import a page from another page.
- Heavy libraries (Recharts, date-fns locales, xlsx helpers) may only be imported from feature
  files, never from `src/components`, `src/lib` or `src/app` (they would land in the main chunk).
  For a chart inside a sheet, `lazy(() => import('./SpendingChart'))`.
- Import lucide icons by name (`import { Coffee } from 'lucide-react'`); never `import * as`.
- `src/dev/` is only reachable in dev builds; do not import it from features (sample data is used by
  the components page and the mock API only).

## Tests

- Pure logic: `*.test.ts` next to it (see `src/lib/*.test.ts`).
- Components/screens: `*.test.tsx` with `renderWithProviders(ui, { path })` from `src/test/render.tsx`
  and a mocked `fetch` (`vi.stubGlobal('fetch', ...)`), see `src/auth/auth.test.tsx`.
- Query by role and visible (Greek) text, as a user would.
- E2E specs in `e2e/` run against the real backend (see Commands); `e2e/integration.spec.ts` covers old links,
  reloads, Back with sheets, report tabs, a lost session and bank logos.

## Routes and links

- Every screen has a URL; the backend serves `index.html` for any non-API path, so every route survives a
  reload and can be bookmarked. Shared groups: `/shared/groups/:groupId` (old `?group=<id>` redirects there).
- Old-app links are redirected by the root route's loader (`src/app/legacy.ts`): `/?panel=<panel>` with
  `month`, `cal_year`/`cal_month`, the `exp_*` / `inc_*` list filters, `settings_section`, `reports_section` (incl.
  the legacy `bank` / `crypto` / `stocks`), `report_year`, `report_account`, `tag`, `investments_section`, `group`,
  `pay_card`. Unknown panels go Home. Not logged in: the login page first, then the target (`?next=`).
- Cross-links: Home budget card -> `/budget?month=`, "Pay" on a card -> `/transfers?pay_card=<id>&month=`,
  `#tags` -> `/reports/tags?tag=`, Home lists -> Expenses / Income / Summary, More page -> every section.

## Vocabulary (Greek)

One word per concept on every screen: λογαριασμός (account; never for a bill), κατηγορία, έξοδο, έσοδο,
καταχώριση (an expense or income entry), κίνηση (anything that moves a balance), μεταφορά (transfer only;
data migration is "εισαγωγή"), επαναλαμβανόμενα / κανόνας (recurring rule), budget, κοινά έξοδα / κοινό έξοδο
(shared), εξόφληση (settling a shared debt), πληρωμή κάρτας (paying a credit card), κατάσταση (card statement).
